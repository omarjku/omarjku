# motion

The animated GIFs on my profile and in my project READMEs are generated by code. No screen recordings, no AI video tools: every frame is a pure function of time, drawn on a `<canvas>`.

```
scenes/<name>.js   draw(ctx, t) for one video
engine/lib.js      easing, timelines, seeded randomness, text and shape helpers
engine/stage.html  loads a scene onto a canvas (open it in a browser to preview live)
render.mjs         headless Chromium draws each frame → PNG → ffmpeg → MP4 + GIF
render-all.sh      renders every scene with the sizes used in the READMEs
```

## Render

Needs Node 18+, `ffmpeg`, Playwright with Chromium, and optionally `gifsicle` (smaller GIFs).

```bash
node motion/render.mjs leyrd --scale 1.5 --gif 1000 --card 440   # → motion/out/leyrd.{mp4,gif} + leyrd-card.gif
node motion/render.mjs leyrd --still 2.5,7                        # single PNG frames, for checking a moment
motion/render-all.sh                                              # everything
```

Frames render in parallel across CPU cores. Because `draw` depends only on `t`, any frame can be rendered on any worker in any order, and every scene ends where it began, so the GIF loops without a seam.

## GIF size

GIFs only store the pixels that change between frames, so the scenes keep backgrounds still and move the subject (the banner's mesh holds still while signals travel along it). That keeps each README GIF around 1–2 MB.

Fonts in `engine/fonts/` are from Google Fonts under the SIL Open Font License: Inter, JetBrains Mono, Instrument Serif, Space Grotesk, Hind Siliguri. If Inter and Inter Display are installed locally they are used first.
